# Qwen 单节点创作面板设计

日期：2026-09-26。状态：用户已批准，功能已实施；实际验证与剩余限制见 HANDOFF.md 最新交付。

## 目标与布局

将当前单节点整合成结果预览、提示词、参数入口和生成操作一体的创作面板。沿用现有 ComfyUI 扩展，不修改 ComfyUI 核心，不引入新的前端框架。

从上到下：作品名称与实际尺寸 → 本次结果参数 → 结果预览与历史切换 → 可排序参考图缩略图 → 支持 @ 标签的提示词 → 参数摘要按钮与生成/取消按钮 → LoRA、推理加速、模型缓存 → 高级设置按钮。

## 已确认交互

1. 参数摘要按钮打开悬浮面板：画幅、输出分辨率、推理强度、种子、排除内容、RTX 超分设置。种子包含数值输入和固定、随机、递增值、递减值四种模式。高级设置也使用悬浮面板，展示模型、CFG、采样器、调度器、重绘强度等；不向下撑开节点，不重复显示种子。
2. 推理强度按钮显示为低18步、中24步、高40步、自定义1～200步；底层旧工作流标识继续兼容。启用有效 LoRA 后切为自定义并保留步数；禁用或移除后不自动切回。有效指已选择文件、启用且强度非0；文件失效时提示，不猜测专用步数。Viggle Turbo 保留专用参数提示。
3. 分辨率提供480p、768p、1K、2K、4K；均按方形等效总像素预算解释，最终宽高随画幅计算并取32倍数。
4. 旧工作流保存的步数保持原值。旧12步显示自定义，旧18步显示低，旧24步显示中；已有自定义模式必须保持，不能仅凭步数反推覆盖。新建节点默认中24步。
4. 提示词输入区和上方缩略图区均接收图片拖入；图片进入参考列表，保留已有文字，不额外创建图片节点。支持删除、排序、@引用，最多10张；标签仍跟随原图片身份。
5. 生成按钮仅提交当前节点及必要上游依赖。提交、排队、运行、取消期间锁定本节点全部编辑入口，保留取消、结果查看、下载和画布导航；超分属于修改操作，同样禁用。
6. 提交时立即防重入；取得任务编号后显示取消。取消仅针对该任务；等待停止确认后解锁，完成/失败也解锁。提交结果不明确或断连时先核对任务状态，不能假定失败并重复提交。
7. 预览区显示生成动画和阶段文字。初始采样预计时间=实际步数×3秒；排队、模型加载、编码、解码不混入采样倒计时。采样开始后按已完成步数和耗时更新估计，标注“约”；不伪造进度或卡在0秒。支持减少动态效果偏好。
8. 结果上方允许重命名，显示实际尺寸和该图生成时的参数快照。修改当前设置不改变旧图信息。重命名修改展示名和下载名，不移动底层文件。
9. 点击结果显示下载、放大查看、RTX超分工具栏。RTX参数为整数倍率1～4、LOW/MEDIUM/HIGH/ULTRA，默认2倍/ULTRA。2倍表示宽高各翻倍。处理选中结果的原图，不重跑生图、不默认对已超分版本再次倍增。
10. 原图与超分版本同时保留；超分完成后切到新版本，失败保留原图。近期历史实施默认保留最近10次成功生成，每次关联原图和超分版本；生成失败/取消不挤掉历史。历史滚出界面不自动删除磁盘文件。

## 兼容与持久化

- 种子复用现有seed与control_after_generate字段；固定/随机/递增值/递减值分别映射fixed/randomize/increment/decrement。当前数值用于本次提交；成功入队后依模式准备下一次值：固定不变、随机抽取、递增1、递减1。沿用ComfyUI有效取值范围与边界规则，不增加用户未要求的步长设置。
- 种子更新在一次成功提交生命周期内只执行一次；提交失败不消耗下一值，断连恢复不再次更新。已入队后取消或执行失败不回退种子；RTX后处理不消耗生图种子。结果快照记录本次真实使用值，不记录为下次准备的值。种子数值和模式均参与生成期间锁定及工作流保存。

- 保留已有输入名、原始位置式 widgets_values 顺序及 image/model/latent/status 输出顺序。新设置只追加字段；历史、显示名称放节点 properties，不保存图片base64。
- 1K/2K/4K仍为1024²/2048²/4096²总像素预算；提示词唯一比例自动选择、手动覆盖、参考图画幅规则保持。
- 负面提示词与CFG设置独立；切换负面词方案不调整CFG，也不显示CFG门槛提示。TE-speed与KV独立；KV关闭必须向核心传off。
- 生图结果保存至ComfyUI output专用子目录，使工作流重开仍可预览；文件缺失时显示缺失状态。历史信息随工作流保存，复制节点时移除活动任务关联但保留可读历史引用。
- 工具栏超分为独立队列任务，不改已有image输出口语义，不自动触发下游。当前节点image仍代表原始生图结果。
- 活动任务用节点properties记录prompt_id、类型、目标结果ID和提交快照，重开后查询queue/history恢复；节点副本不得继承取消原任务的控制权。

## 技术证据与限制

- 本地 POST /prompt 支持 partial_execution_targets。取消采用 POST /api/jobs/{id}/cancel 原子接口，避免先查队列再 interrupt 的竞态；不支持时提示，不回退全局中断。
- 本地RTXVideoSuperResolution支持图片、倍率1～4及ULTRA。已实测 2 倍 ULTRA GPU 超分及排队/运行取消；4K 和高倍率显存尚未验证；无法立即中断的调用须保持“取消中”直到后台停止。
- 已新增 UI 结果数据和持久保存，保留原有四输出。项目不是 Git 仓库，实施前已做文件备份。

## 验收

悬浮面板不撑高节点；保存重开保留参数和历史；拖图不新增节点；LoRA切自定义不改步数；当前节点定向提交且取消不影响其他任务；失败/断连可恢复状态；RTX仅处理既有原图；历史参数与实际输出一致；旧工作流和已有节点输出保持兼容。
